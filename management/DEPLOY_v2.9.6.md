# 다중 PC 수집 제어 배포

1. 기존 관리 Apps Script에 Code.gs, SafeMode.gs, ErpTurn.gs 기능을 반영한다. 단일 파일 프로젝트는 세 파일 내용을 합쳐 Code.gs에 넣는다. 기존 웹 앱 URL을 유지해 새 버전으로 갱신한다.
2. 사용자관리 H1은 수집순서다. 빈칸이면 등록 행 순서가 기본값이며, 수집을 실제 요청한 PC만 대기한다. 이상호 이름은 서버가 D열에서 읽어 최우선으로 판정한다. 클라이언트가 이름/순서를 보내거나 G열 접속 표시를 읽어 우선권을 정하지 않는다.
3. 관리 API GET의 coordination_version=2를 확인한다. acquire/renew/release/cancel의 token 및 등록 PC 권한 검사를 통해 동시 요청이 차단되는지 검증한다.
4. 설치파일 게시 및 테스트 통과 후 생산3팀 최신버전을 2.9.6으로 변경한다. 구버전은 중앙 허가를 따르지 않으므로 모든 PC를 업데이트한다.

실제 ERP 호출은 한 건씩이다. 새 요청은 약 5초의 합류 시간을 거쳐 우선순위가 결정되며, 대기는 20초 간격의 직접 신호로 유지한다. 수집 중 45초마다 허가를 갱신한다. 대기 신호가 3분간 없으면 제거한다. 실행 PC가 사라지면 마지막 갱신 후 10분의 허가가 만료되고 2분의 서버 처리 대기를 거쳐 다음 PC를 허용한다. API 실패 후에는 10분의 전체 보호 대기를 적용하며 각 PC의 APS 실패 재시도는 10·20·40·60분으로 늘어난다.

같은 run_key의 Backward 전체 조회는 PC별 성공 후 생략한다. 동일 회차의 WIP 시각 변화는 저장 메타데이터만 갱신해 기존 Backward 수량을 유지하고 실시간 계산을 계속한다. 관리 API가 준비되지 않거나 통신이 끊기면 원본 API 직접 조회로 우회하지 않는다.
