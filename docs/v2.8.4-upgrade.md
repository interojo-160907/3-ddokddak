# v2.8.4 설치 및 데이터 전환

## 소스와 배포

기준 소스는 `v2.8.3` (`46e1022`)이며, 준비 브랜치는 `codex/production3-v2.8.4`입니다. 원격 main은 더 오래된 2.6.2 계열이므로 main의 내용을 덮어쓰거나 되돌리지 않습니다.

앱, EXE 버전 리소스, Inno Setup 버전 및 배포 문서를 2.8.4로 맞췄습니다. `gui_app_pyside6.py`가 정식 진입점이며 자동·수동 수집이 활성화됩니다. `scripts/backward_preview.py`는 외부 수집과 관리 서버 호출을 끈 별도 검토용 실행기이므로 정식 사용자 실행에 사용하지 않습니다.

배포 준비가 끝난 커밋에서 브랜치를 push한 뒤 `v2.8.4` 태그를 push하면 기존 GitHub Actions가 실행 파일과 설치 파일을 빌드하고 테스트 성공 후 Release를 게시합니다. 태그 push는 사용자에게 업데이트가 노출되는 배포 작업입니다. 이 준비 작업에서는 원격 태그나 Release를 만들지 않습니다.

## 데이터 보존

- 레지스트리의 기존 DataRoot와 수집 주기·사용자 설정은 유지합니다.
- 새 APS DB: `<DataRoot>/backward-v1/process-status/aps_process_status.sqlite`
- 새 실시간 계산 DB: `<DataRoot>/backward-v1/live-production-need/current_production_need.sqlite`
- 새 재고 캐시: `<DataRoot>/backward-v1/inventory-status/`
- 초기 수집 상태: `<DataRoot>/backward-v1/settings/`
- BOM, 생산실적, 리드지와 설정은 기존 위치를 사용합니다.
- 이전 Plan DB와 계산 캐시는 새 영역으로 복사하지 않습니다. 수화 API 설정 파일만 새 위치에 없을 때 가져옵니다.
- 2.8.4 제거 시 데이터 및 저장 위치를 보존합니다. 이전 버전의 제거기는 이 변경이 적용되어 있지 않으므로 기존 사용자는 먼저 제거하지 말고 설치 파일로 직접 업데이트합니다.

## 초기 전체 수집

설치·업데이트·같은 버전 재설치는 초기 수집 완료 표시와 전체 수집 보고서만 지웁니다. 실제 DB나 사용자 파일은 지우지 않습니다. 첫 실행은 수집 주기가 중지여도 전체 수집을 시작합니다.

1. BOM 전체, Backward APS 전체, 생산실적 전월~당일을 새로 받습니다. APS 원천 시각이 같아도 건너뛰지 않습니다. 생산실적은 날짜별로 나누고 동시 요청 수를 제한합니다.
2. APS 성공 후 WIP, 5개 창고, 수화 지시와 재고 결과를 계산합니다. 초기 전체 수집은 이전 창고 응답을 재사용하지 않습니다.
3. 기본 수집 실패 시 초기 완료 표시를 남기지 않고 5분 간격으로 재시도합니다. 기본 수집 성공 후 실시간 단계만 실패한 경우 기본 단계 완료만 기록하고 실시간 단계만 재시도합니다.
4. 모든 단계 성공 후에만 `completed_version: 2.8.4`를 기록합니다. 이후 정상 수집 주기로 돌아갑니다. 사용자가 취소한 경우에는 즉시 자동 재시작하지 않고 기존 취소 유예를 적용합니다.

자동·수동 수집과 정리는 프로세스 간 파일 잠금으로 직렬화합니다. 충돌 시 기존 작업을 죽이지 않고 다음 수집으로 넘깁니다. 수집 프로세스가 비정상 종료되면 OS가 잠금을 해제합니다.

## 검증 범위

- 회귀 테스트에 기존 파일 보존, 설정만 이전, DB 경로 일치, 누락 DB 재수집, 초기 강제 전체 수집, 부분 실패 재시도, 프로세스 충돌·강제 종료 후 잠금 해제 검증을 추가했습니다.
- 기존 Backward 원천 수량·회차·WIP 검증은 `tests/test_backward_source.py`와 `docs/BACKWARD_VALIDATION_20261012.txt`에 기록되어 있습니다.
- GitHub 배포 과정에 신규 설치, 같은 버전 재설치, 제거 후 데이터 보존 및 재설치 검증을 추가했습니다. 기존 모든 공개 버전의 직접 업데이트 검증과 2.7.10 복구 검증도 유지합니다. 설치 테스트는 실제 사용자 PC가 아닌 일회용 GitHub runner에서만 실행합니다.
- 2026-10-12 15:08 실제 API 전체 수집 시도에서는 서버가 새 APS 회차를 적재 중이어서 완료되지 않은 APS를 사용하지 않고 후속 계산을 보류했습니다. 이 결과를 정상 전체 수집 완료로 간주하지 않습니다.
- WIP에는 회차 키가 직접 제공되지 않습니다. 현재 제공되는 완료 상태·시각·행 수·WIP 스냅샷 일치로 검사하며, 서버 측 직접 회차 키 이상의 보장을 주장하지 않습니다.
