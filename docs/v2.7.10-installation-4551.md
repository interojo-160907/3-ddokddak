# v2.7.10 설치 오류 4551 조사 및 서명 준비

2026-09-19. **구글시트 변경 보류. 서명된 교체 설치파일은 아직 게시하지 않았다.**

## v2.7.9와 실제 배포 파일 비교

| 항목 | v2.7.9 | v2.7.10 |
|---|---|---|
| 설치파일 서명 | NotSigned | NotSigned |
| Inno Setup | 6.7.1 | 6.7.1 |
| PyInstaller / Python | 6.22.3 / 3.13.15 | 6.22.3 / 3.13.15 |
| GitHub Windows 이미지 | windows-2025-vs2026, 20260907.229.1 | 동일 |
| 설치파일 크기 | 77,843,810 bytes | 77,752,349 bytes |
| 자동 업데이트 코드 | services/update_service.py | 바이트 변경 없음 |
| 임시폴더에서 설치 본체 실행 | Inno 기본 방식 | 동일 |

두 버전의 설치 스크립트 차이는 버전 문자열과 재고 현황 디렉터리 두 개의 생성 코드 제거뿐이다. 설치 권한, 압축 방식, 설치 위치, AppId 및 실행 방식은 같다. 요구 패키지와 실제 빌드에서 설치한 패키지 버전도 같다.

다운로드한 파일의 SHA-256은 GitHub 배포 자산의 digest와 일치했다. 이는 우리가 받은 파일에 대한 검사이며, 직원 PC가 받은 파일까지 확인한 것은 아니다.

- v2.7.9: `8b34302d585ef80f4213ad83391d2fc68e0440e3281fecf2d8709ba260154107`
- 기존 v2.7.10: `baddf74655fff923f8846eb8c891673f84d61cc51bc74677196e5c414162e04a`
- [v2.7.9 빌드](https://github.com/interojo-160907/3-ddokddak/actions/runs/35403181787)
- [v2.7.10 빌드](https://github.com/interojo-160907/3-ddokddak/actions/runs/35404927207)

## 확정 사실과 미확정 원인

사용자가 전달한 오류는 `4551 / 애플리케이션 제어 정책에서 이 파일을 차단했습니다 / 임시 디렉터리에서 파일을 실행할 수 없습니다`이다. Windows의 파일 실행 차단이며, 앱의 재고 계산이나 API 호출 오류를 나타내는 메시지가 아니다.

**서명이 없다는 사실만으로 2.7.10에서 처음 차단된 이유를 확정할 수 없다.** v2.7.9도 서명이 없었다. Smart App Control은 서명 외에 클라우드의 파일 신뢰 판단도 사용한다. 이후 수신한 직원 PC 기록으로 SAC와 차단 파일은 특정했다(아래 절). 새 파일의 판정 차이 또는 이전 설치 때의 정책 상태 차이 중 왜 이번 버전에서 차단됐는지는 여전히 미확정이다.

기존 10개 버전 직접 업데이트 테스트는 일반 GitHub Windows 환경에서 통과했다. 해당 직원 PC의 App Control 정책에서 통과한 테스트는 아니다. 이 둘을 동일하게 안내하지 않는다.

## 해당 PC에서 확인할 자료

### 직원 PC의 실제 3077 기록 수신

사용자가 제공한 XML에서 다음을 확인했다. 개인정보인 사용자명과 SID는 이 문서에 옮기지 않는다.

- 발생 시각: 2026-09-18 23:24:14 UTC = **2026-09-19 08:24:14 KST**.
- 실행 주체: `Temp/DdokddakProduction3/updates/ddokddak-production3-setup.exe`.
- 차단 대상: `Temp/is-3RHG2NHOG6.tmp/ddokddak-production3-setup.tmp` (Setup/Uninstall).
- PolicyName: `VerifiedAndReputableDesktop`.
- PolicyGUID: `{0283ac0f-fff1-49ae-ada1-8a933130cad6}`. Microsoft 공식 표의 **Smart App Control 활성 정책**과 일치한다. 이 사건의 차단 정책은 이제 미확정 상태가 아니다.
- Requested Signing Level 2 / Validated Signing Level 1, Status `0xc0e90002`.
- 차단 파일 SHA256 Flat Hash: `D121E64759206C5BF8211ECF71FEB8490BF72DC4F43AB95D05CB32A32ABD24E6`.
- 위 해시는 **내부 TMP 파일**의 해시이므로 배포 EXE의 SHA256과 다르다고 손상으로 판정하면 안 된다.

확정된 것은 SAC가 설치 본체의 내부 임시 실행파일을 차단했다는 사실이다. 왜 이전 버전은 허용됐는지, 이 임시 파일에 대한 클라우드의 구체적인 판단 이유까지 이 이벤트가 설명하지는 않는다. `Enterprise signing level`이라는 문구만으로 회사가 만든 별도 정책이라고 해석하지 않는다.

근거: [Microsoft 기본 App Control 정책과 GUID](https://learn.microsoft.com/ko-kr/windows/security/application-security/application-control/app-control-for-business/operations/inbox-appcontrol-policies).

현재는 해당 증거로 차단 대상·정책을 특정했으므로 같은 기록을 다시 요청할 필요는 없다. 아래는 추가 조사가 필요한 경우의 수집 방법이다.

이벤트 뷰어 → 응용 프로그램 및 서비스 로그 → Microsoft → Windows → CodeIntegrity → Operational에서 오류 발생 시각의 **3077**을 확인한다. 차단 파일 경로, 파일 해시, Policy ID와 동일 ActivityID의 3089 서명 정보를 함께 확인한다. 해당 기록의 3099는 정책 식별에 도움이 된다.

선택적으로 `scripts/collect-install-block.ps1`을 해당 PC에서 실행하면 최근 3일 기록(최대 1,000건)과 Windows/SAC 상태를 바탕화면에 저장한다. 정책 변경·설치 실행·외부 업로드는 하지 않는다. 파일 경로와 다른 프로그램명이 포함될 수 있으므로 공유 전에 검토한다. 스크립트 실행도 정책에 막히면 우회하지 말고 이벤트 뷰어에서 기록을 내보낸다.

```powershell
.\scripts\collect-install-block.ps1 -InstallerPath 'C:\정확한경로\ddokddak-production3-setup.exe'
```

## 이번 소스 보완

- 앱 기능은 v2.6.4, 앱·설치파일 버전은 2.7.10을 유지한다.
- 서명 설정이 없으면 릴리스 빌드를 중단한다. 서명 없는 파일을 대신 게시하지 않는다.
- 패키지의 EXE/DLL/PYD를 검사하고, 기존 유효한 Python/Qt 서명을 보존하며 미서명 파일만 정식 인증서로 서명한다. 손상되거나 신뢰할 수 없는 기존 서명은 덮어쓰지 않고 실패 처리한다.
- Inno `SignTool=ddokddak`, `SignedUninstaller=yes`로 설치 본체·임시 실행 복사본·제거 프로그램에 서명한다.
- 설치 전 서명·타임스탬프를 검사하고, 이전 버전별 실제 업데이트 후 앱·제거 프로그램·의존 파일 서명을 다시 검사한다.
- 실행 중인 프로그램, 데이터, 직원 PC의 보안 정책을 변경하지 않는다.

## 필요한 서명 설정

현재 확인한 로컬 인증서 저장소와 GitHub Actions 설정에는 사용 가능한 코드서명 인증서/서비스가 없다. 회사가 보유한 정식 코드서명 수단을 확인해야 한다. 비용이 발생하는 서비스 가입, 인증서 발급, 자기서명 루트 신뢰 등록은 수행하지 않았다.

GitHub 빌드는 Microsoft Artifact Signing의 **Public Trust** 프로필과 Azure OIDC 연결을 준비해 두었다. 조직 신원 검증, 계정/프로필 생성, Certificate Profile Signer 권한 및 대상 저장소·릴리스 태그에 제한된 OIDC 신뢰 설정이 선행되어야 한다.

- Actions secrets: `AZURE_CLIENT_ID`, `AZURE_TENANT_ID`, `AZURE_SUBSCRIPTION_ID`
- Actions variables: `ARTIFACT_SIGNING_ENDPOINT`, `ARTIFACT_SIGNING_ACCOUNT`, `ARTIFACT_SIGNING_PROFILE`
- Korea Central의 공식 endpoint: `https://krc.codesigning.azure.net` (실제 계정 지역과 일치해야 함)
- 비공개 키/PFX는 저장소나 빌드 로그에 넣지 않는다.
- 로컬의 회사 인증서를 사용할 때는 SDK SignTool 경로 `DDOKDDAK_SIGNTOOL`과 현재 사용자 My 저장소의 `DDOKDDAK_CERT_THUMBPRINT`를 사용한다. 해당 키 접근 권한과 신뢰 체인은 별도로 갖춰져 있어야 한다.

서명 성공 경로와 직원 PC의 설치 성공은 **아직 검증 전**이다. 서명 검증 통과가 모든 회사 보안 정책에서의 허용을 보장하지는 않는다.

## 구글시트 변경 조건

정식 서명 수단 연결 → 서명된 2.7.10 생성 → v2.6.4 및 v2.7.1~v2.7.9 직접 업데이트·데이터 보존 재검사 → 문제가 난 직원 PC에서 정책을 유지한 채 설치 확인 → 교체 배포 자산과 해시 확인 후 구글시트 버전을 2.7.10으로 변경한다.

기존 v2.7.10 태그/미서명 자산을 새로 검증한 것처럼 재사용하거나, 아직 서명하지 않은 파일을 해결판으로 게시하지 않는다.
